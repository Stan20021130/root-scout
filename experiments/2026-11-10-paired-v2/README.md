# 2026-11-10：单轮与多轮的受限预算对照

这次实验比较现有 `one_shot` 和 `causal` 策略。计划覆盖仓库中的 32 个人工构造开发样本，每题两种策略各运行一次。先选 12 题试跑，查看试跑结果后再按数据集原顺序扩展到其余 20 题。模型输出有随机性；这些样本不是盲测或真实题目总体的代表。

最终有 **20 组成对结果包含完整模型响应、可用于下列代理比较**。另 9 组的两次调用均因服务端 HTTP 502/503 失败，没有完整模型响应；剩余 3 组没有运行。多轮结果中有 2 次在得到模型响应后因预算预留而提前停止。

| 指标 | causal | one_shot |
|---|---:|---:|
| 可比较组数 | 20 | 20 |
| 这些组的模型调用次数 | 32 | 20 |
| 这些组的已确认 Token | 181,561 | 98,342 |
| 缺陷样本：首要候选行与标注行重合 | 10/12 | 10/12 |
| 缺陷样本：同时关联完全相同的标注触发输入 | 10/12 | 10/12 |
| 正常样本：活动缺陷或未分类候选 | 0/6 | 0/6 |
| 题意不足样本：无活动缺陷或未分类候选 | 0/2 | 1/2 |

在这 20 组成对结果里，`one_shot` 的已确认 Token 少 **45.84%**，调用次数少 **37.5%**。这不是实际账单降幅：缓存、输入与输出的价格不同，且失败调用的用量未知。按历史 `未命中输入:命中输入:输出 = 1:0.02:4` 权重得到的指数分别是 221,424.08 和 101,075.20，也只是可复算的成本代理。

质量数字不能当作准确率或非劣效证明。严格锚点解析导致一些位置表述未计入：例如 `range-endpoint-cpp17` 的单轮结果写了第 8 行和行内片段，但解析器只接受独立行号或完整源码行；`range-double-cpp17` 的多轮结果引用的是行内片段。两例的文字描述都指向了标注的区间端点问题，但这不证明其他描述正确。首要位置、单个冻结触发输入也不能覆盖全部根因；两种策略在个别题目的得分相反，汇总相同会掩盖逐题变化。

## 预算与失败账本

两组使用同一模型 `deepseek-v4.1-flash`、`baseline` 提示、`low` 推理、固定输出策略、单次诊断 60,000 Token 准入上限、180 秒墙钟上限、同一 Docker 镜像和执行并发 1。每题交替先运行的策略。设置单题上限会使当前 `native_delta` 适配器回退到普通 Chat Completions 传输，所以这些数值不能直接代表默认的无限额原生传输。模型可以看到控制器给出的可信测试观察；缺陷行和预先冻结的根因说明没有放入请求。

本次全部尝试的已确认用量合计 **279,903 Token**。另外有 **668,770 Token 未知用量预留**，这只是预算账本中的保守预留，不是实际使用量或实际收费。服务代理依次返回了 3 次 502 和 15 次 503。评测运行器本应在首次传输失败后停下，但原运行器未覆盖这一条件，导致后续尝试；到达预设的整组准入止损后停止。原始失败记录仍在证据包中，没有自动重试。

故障后只读健康检查显示代理仍可访问，但当前 realm 的可用账户数为 0；这是排查线索，不能仅凭这一项确定 502/503 的原因或实际计费。

运行器现已增加传输故障、超时和流不完整时的停机保护；离线评分也不再把没有完整模型响应的状态算作成功弃答。原始运行器和原始评分器分别保留为 `run-original.py`、`evaluation-original.py`，用于校验此次实验的代码哈希。

## 决策和复算

当前保留 `causal` 为默认策略。`one_shot` 可以作为用户主动选择的低调用模式，但本次结果不足以证明它适合无条件替代多轮。继续实验前应先核对服务商侧实际账单、恢复上游服务，并为未完成样本另设预算和批次；不能把现有失败覆盖成成功或按零成本计入。
