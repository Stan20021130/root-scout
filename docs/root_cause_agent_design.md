# RootScout 产品与执行契约

版本：Probe 1 · 日期：2026-11-01 · 状态：最小可运行改造已实现，模型诊断质量待独立验收。

## 定位

RootScout 是面向 Coding Agent 与工程师的**证据驱动型白盒质检探针**，嵌入开发流水线，承担对抗测试与因果审查。它读取需求与原件，寻找可复现破坏，输出事实、原始位置与验证缺口；源码修复由调用方负责。

当前实现的执行对象为单份 Python 3、C++17/20 的 stdin/stdout 算法程序。这个产品方向可以扩展到工程代码，但本次没有增加多文件仓库执行、服务环境、通用 API 测试或自动修复平台。

## 最小闭环

~~~mermaid
flowchart LR
    A[需求与原件快照] --> B[合法域对抗测试]
    B --> C[原版可信比较]
    C --> D[隔离局部干预]
    D --> E[事实报告与证据账本]
    E --> F[调用方审查与修复]
    F --> G[反例及基线复测]
~~~

控制器负责权限、预算、来源、执行和证据保留。模型负责提出主张、选择区分问题的实验、解释观察和标明不确定性。模型不能更改原始请求、执行环境、预算或可信预期。

## 三种信息必须分别表达

| 信息 | 可作出的结论 | 不足以推出 |
|---|---|---|
| 实际观察 | 某版本在某输入上得到特定输出、状态和耗时 | 需求语义、模型解释正确 |
| 可信反例 | 合法输入、可信预期、原版成功运行且输出不匹配 | 确切病因、唯一根因、最小反例 |
| 干预对照 | 某隔离变体在相同输入和预期下改变了比较结果 | 生产修复正确、机制语义通过独立裁决 |

模型主张永久保留，但不能因为被保存、被重复、引用一个动作或取得补丁改善就变成事实。

主报告中的 findings 必须关联原版真实反例。description、trigger 和位置归因仍标注 unverified。没有反例关联的候选在主报告列 ID，在完整账本与兼容候选视图中保留原文。这样既保留发现，也不把推测包装成诊断事实。

## 原始行号与因果位置

每次报告固定源码 SHA-256、原始行数和可用的来源文件路径。显式的 line N / lines N-M / LN 位置主张只有落在原始源码范围内，才生成带原文的 source_anchors；模糊描述不会猜测成行号。

source_anchors 证明位置可在原件找到，不证明该行造成反例。原版起点的干预另提供原始编辑行范围；派生版本行号不冒充原始行号。

当前 isolated_contrast_observed 要求同一工具动作关联一个候选、只做一个非空变化、父版本是 original、原版与变体在同输入及可信预期下成功运行，并观察到原版分歧消失。联合干预或派生链保持混杂；原通过测试在变体失败时另记回归。

所有自由文本因果解释保持 semantic_cause_verified=false。独立语义裁决尚未实现。

## 来源与输入域

调用方测试必须显式声明 trusted、expected_source、legal_input 和 legal_input_source，且输入与预期是字符串。MCP 不再自动填充这些声明。

题面样例保留原文出处；内建 Oracle 由控制器验证调用方契约并重算结果。模型 Bash 结果、未审定暴力程序、模型心算答案和未知域输入只能提供观察，不能提供可信 expected。调用方额外输入保证与 statement 分开存储，防止改写题面版本和 Oracle 哈希绑定。

反例最小性必须有缩减检查；当前统一标记 not_established。性能与全域正确性同样不从有限功能测试推出。

## 执行权限

- 只读取调用方传入的源码与规范文件。
- 提交、对抗脚本和派生版本只能在 Docker 运行，无宿主机执行降级。
- 沙箱挂载控制器创建的临时源码快照，原始仓库不进入可写挂载。
- 临时工作区内允许构造测试和派生程序；探针没有写回调用方源文件的工具。
- MCP 不接受内部镜像参数、任意执行器、legacy 引擎或任意输出路径。
- 同一诊断共享轮数、Token、墙钟和执行单元预算。Docker 不可用时停止模型探索。

## 接口与材料

保留 rootscout_diagnose 和 rootscout_verify_fix 两个 MCP 工具，CLI diagnose/replay 继续可用。主入口复用已有 v2 候选与动作循环，不新建 Agent 框架。

统一主交付 probe.json 使用 rootscout.probe.v1。case_state.json 保存完整可重放状态，result.json 保留旧候选视图。MCP 每次调用创建独立持久证据目录，控制器失败时保留进度和错误。文件哈希只验证一致性。

工具执行失败、模型协议错误、预算不足、缺少可信比较和候选未完成语义验证都作为明确缺口。即使诊断后半程失败，前半程取得的反例仍交付；没有证据的空列表不能被包装成程序正确。

## 验证与验收

工程回归覆盖：

1. 未验证候选、缺少来源、非法域、超时与编译失败不能产生可信反例。
2. 原始行锚点、单候选单编辑对照、联合干预和回归分别表达。
3. Docker 缺失时不调用模型、不执行提交；MCP 内部参数不能越权。
4. 原文件哈希在工具调用前后保持一致，返回后证据文件仍存在。
5. 截断复现材料标记不完整，完整账本与哈希可核查。
6. 旧候选结果和 CaseState 验证、重放继续保留。

固定模型响应与真实 Docker 用于验证执行和交付契约，不构成模型诊断质量验收。后续质量验收须使用独立题目、合法域审定、可信输出与独立语义根因标注，分别统计反例发现、位置准确、解释准确、误报、弃答、成本和延迟。

旧文档中的全根因命中率、精度、Token 或成本收益目标均不作为当前承诺。历史说明见 [README_LEGACY.md](README_LEGACY.md)。
